## 已落地

| 环节 | 以前的问题 | 当前实现 |
|---|---|---|
| 决策状态 | 首页、预算、证据卡分别判断，缺少闸门可能被当作未阻塞 | 共用 `tools/decision_state.py`，分别显示行情、市场、候选、账户；缺失不等于通过 |
| 数据新鲜度 | 有一条报价即可显示可用；未来账户时间可能被判新鲜 | 检查行情生成时间和每只必需标的报价时间，账户未来时间拒绝；未知可卖不显示为0或推断T+1 |
| 刷新入口 | 缺少可选 `portfolio.local.json` 时无代码可刷新 | 默认读取最新本地持仓、3个市场代理、最多3张研究卡；无账户仍可刷新基准 |
| 历史证据 | 聊天已核账，工作台仍只有纸面记录 | 导入带来源哈希和覆盖期的历史核账摘要；与逐笔成交账本明确分开 |
| 账户事实 | 旧持仓快照未同步 | 导入最后已确认的历史持仓；混时点现金、未知可卖、缺交割单仍标待核验，不冒充今日账户 |
| 零值处理 | 最大回撤0被`or -1`替换；缺涨幅可能被当平盘 | 明确区分零值、缺失和无效数值 |
| 诊断回测 | 信号收盘即按同价入场，重叠收益串乘 | 次日开盘模拟入场；至少隔一交易日退出；各期限独立、非重叠交易；按每日收盘估值计算回撤 |
| 候选传递 | `market_gate_ok`未传入模块导致候选恒被清空 | 传入实际市场许可，完整扫描要求同时适用于盘后；测试覆盖通过及拒绝路径 |
| 通知 | 重复候选重复发；闸门撤回不通知；静默记录不保留 | 当日公共事件指纹去重，已开放变关闭可提醒，SMTP失败不消费事件；CI保存公共审计工件和状态缓存 |
| 页面 | 顶部原因过长、历史模板占据大量篇幅 | 首页精简状态，四项条件展开说明，历史公开维护记录折叠，新增真实复盘入口 |

## 规则边界

规则版本 `2026-09-18.1`。

- `intraday_two_of_three_ma20`：保留盘中三核心代理至少两只MA20上方且非跌的条件。
- `postclose_benchmark_ma20`：保留盘后基准MA20条件。
- 两者共用覆盖、广度和原因表达；策略条件不同会明确标profile，不再统称同一总闸门。
- 本地账户30分钟、报价及行情文件5分钟、雷达报告90分钟的新鲜度用于可执行复核。收盘/休市数据可供研究，不能据此宣称实时。
- 账户总资产、现金、市值必须有效且勾稽；已核验成交、明确可卖数量、同时点信息是新增复核的条件。场外资金不自动并入分母。
- 新增许可关闭时仍显示已有持仓供风险复核，不自动产生卖单。

## 回测修订的实际含义

`tools/signal_diagnostics.py` 的方法版本为 `next-open-nonoverlap-2026-09-18`。1/3/5日含义是从下一交易日开盘入场起，间隔相应交易日后于收盘模拟退出；因此最短期限也不假设A股当日买入当日卖出。每个期限单独运行，不能把三个期限叠成一个组合收益。

这仍是小样本、样本内诊断，非完整交易仿真：未模拟真实排队成交、涨跌停价、资金竞争、逐标的税费和完整点时股票池。零成交量及一字价入场/退出日跳过；每日收盘回撤不等于盘中最大回撤。保留原统计门槛，未经证据不提高交易许可。

旧报告是历史快照，没有被重写为新方法结果。需要用新代码重新生成研究报告后，才可以比较新统计；不能把旧方法胜率称作新版本证据。
