# A股选股框架 v5：技术面 + 基本面（财务因子）结合

> 版本：v5（2026-09-03 升级）
> 核心变化：**从纯技术面升级为技基结合**，新增第 6 类「基本面」财务因子（净利增速 / 营收增速 / 筹码集中度 / 龙虎榜资金关注）。
> 数据层仍走星耀数智 AmazingData SDK，逻辑层在 v4 三闸门 + 多因子基础上，增加「两段式」财务二次排序。

---

## 一、v4 → v5 改了什么

| 维度 | v4（纯技术面） | v5（技术 + 财务） |
|---|---|---|
| 打分因子 | 5 类技术因子（满分 100） | 技术 5 类（100）+ 财务 4 类（30）= 满分 130 |
| 财务维度 | 无 | 净利增速 10 + 营收增速 5 + 筹码集中 10 + 龙虎榜 5 |
| 执行方式 | 一段式（技术面一次筛完） | **两段式**：先技术面筛候选 → 仅对候选拉财务二次排序 |
| 排序依据 | 技术分 | 综合分（技术 + 财务），保留两个独立分数便于对比 |

**为什么两段式？**
全市场 5215 只，若每只都拉财务（利润表 + 股东户数 + 龙虎榜），需 5200 次请求，慢且浪费。技术面先筛出约 300~400 只候选，再只对这 300 只拉财务，总耗时可控。

## 二、财务因子设计（新增，满分 30）

| 因子 | 分值 | 指标 | 打分规则 |
|---|---|---|---|
| 净利润增速 | 10 | 最新报告期归母净利 vs 去年同期 | 见下方「增速性质稳健性修正」（扭亏/低基数/亏损特殊处理） |
| 营收增速 | 5 | 最新报告期营收 vs 去年同期 | >20% 得5、>10% 得4、>0 得3、>-10% 得1、更差得0 |
| 筹码集中度 | 10 | 最新股东户数 vs 前期 | 户数减 >8% 得10、>3% 得8、<0 得6、<+5% 得3、更多得0 |
| 资金关注度 | 5 | 近3个月是否上龙虎榜 + 净买入 | 上榜且净买入得5、上榜净卖出得2、上榜无净额得3、未上榜得0 |

**核心逻辑：**
- 业绩（净利/营收增速）看「成长性」，增速越高越好。
- 筹码集中度看「主力收集」：股东户数减少 = 筹码向主力集中 = 拉升前兆。
- 龙虎榜看「游资/机构关注」：上榜且净买入 = 资金真金白银进场。

### 增速性质稳健性修正（净利润增速因子专用）

净利增速是一个容易「失真」的指标，直接拿同比数打分会把虚高/失真当利好。v5 引入 `_growth_nature(cur, prev)` 先判断增速的**性质**，再据此打分：

| 性质 | 判定条件 | 处理 | 打分 |
|---|---|---|---|
| 扭亏 | 去年净利 ≤0，今年 >0 | 无法算同比，但属重大改善 | 固定 8 分 |
| 低基数 | 去年净利为正但 < 今年净利的 **20%** | 增速虚高（如 1561%），承认增长但不过度奖励 | 封顶 7 分 |
| 亏损 | 今年净利 ≤0 | 无增长可言 | 0 分 |
| 正常 | 其余 | 按增速分档：>30% 得10、>15% 得8、>0 得6、>-10% 得3、更差得0，>200% 封顶 10 分 | 见左 |

**低基数阈值为什么是 20%？**
半年报/季报净利绝对量小、波动大。实测一博科技去年 384 万 / 今年 6383 万，增速 1561.5%，本质是小基数爆发而非真实高成长。若用 5% 阈值（去年 < 今年×5%）会漏判（384万 > 6383万×5%=319万），阈值提到 20% 才能正确标记。海思科（560.8%）、一博科技（1561.5%）均已正确打上「低基数」标签。

**输出标记：** 打印时净利增速会带性质后缀，如 `净利增速1561.5%(低基数)`、`净利增速560.8%(低基数)`，正常票不加后缀，便于一眼识别失真增速。

## 三、星耀财务接口关键字段（实测确认）

### 1. 利润表 `get_income(codes, is_local=False)` → `{code: DataFrame}`
```
REPORTING_PERIOD   报告期 YYYYMMDD（int）
REPORT_TYPE        1=Q1 / 2=半年报 / 3=Q3 / 4=年报（⚠️ 字符串类型，需 astype(int)）
STATEMENT_TYPE     报表口径：1=合并报表标准口径（⚠️ 用这个！其余是母公司/调整口径）
OPERA_REV          营业收入
NET_PRO_EXCL_MIN_INT_INC  归母净利润
NET_PRO_INCL_MIN_INT_INC  含少数股东净利
BASIC_EPS          每股收益
```

### 2. 股东户数 `get_holder_num(codes, is_local=False)` → DataFrame
```
MARKET_CODE / ANN_DT / HOLDER_ENDDATE / HOLDER_NUM / HOLDER_TOTAL_NUM
```

### 3. 龙虎榜 `get_long_hu_bang(codes)` → DataFrame
```
MARKET_CODE / TRADE_DATE / REASON_TYPE_NAME / BUY_AMOUNT / SELL_AMOUNT / TOTAL_AMOUNT / TOTAL_VOLUME
```

### 4. 资产负债表 `get_balance_sheet` —— ⚠️ 接口不稳定（查询失败）
ROE = 归母净利 / 归母净资产，需要资产负债表。但该接口实测连续 3 次「查询失败」，故 **ROE 暂不纳入**，用净利增速替代。待接口恢复后可补上 ROE 因子。

## 四、三个关键坑（踩过，务必记住）

1. **REPORT_TYPE 是字符串**：`df["REPORT_TYPE"] == 4`（int）永远匹配不到，必须 `astype(int)` 或比较 `'4'`。
2. **STATEMENT_TYPE 多口径重复**：同一报告期有合并报表(ST=1)、母公司(ST=2)、调整口径(ST=6/7/9/51) 多行，必须只取 `STATEMENT_TYPE=1`（合并标准口径），否则同比会错。
3. **取最新报告期而非年报**：最新数据往往是半年报(REPORT_TYPE=2)而非年报，若死等 REPORT_TYPE=4 会拿到陈旧的 2021 数据。正确做法是取「最新报告期」与「去年同期同报告期」对比。

## 五、运行

```bash
# 需用 anaconda python（SDK 装在 D:\anaconda\Lib\site-packages\AmazingData）
D:/anaconda/python.exe stock_screen_v5.py --top 20     # 全市场（技术+财务）
D:/anaconda/python.exe stock_screen_v5.py --quick      # 快速模式（高价活跃票 800 只）
D:/anaconda/python.exe stock_screen_v5.py --no-fund    # 只看技术面（等价 v4）
```

输出：`screen_result_v5.json`，每只含技术分 + 财务分 + 综合分 + 财务明细（净利/营收/筹码/龙虎榜）。
